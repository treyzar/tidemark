# Dynamic Island для Windows 11 на Rust — план реализации

## 1. Цели по ресурсам (бюджет)

| Метрика | Цель |
|---|---|
| CPU в покое (свёрнутый остров) | ~0 % — поток UI спит в `GetMessageW`, никаких таймеров-поллеров |
| CPU во время анимации | < 1–2 % (GPU-композиция, перерисовка только на время перехода) |
| RAM в покое | < 20 МБ (private working set; поднято с 15 после этапа 4 — WinRT/звук/WIC для медиа дают ~+5 МБ) |
| Размер .exe | < 5 МБ (release, LTO, `opt-level="z"`, `panic="abort"`, strip) |
| Запуск | < 150 мс до появления острова |

**Замер после этапа 1** (2560×1440, 125 %): exe 347 КБ, private 4–5 МБ, CPU в покое 0 мс/10 с, цикл «раскрыть + свернуть» ≈ 270 мс CPU.
**Замер после этапа 2** (плитки, текст, жидкий край): exe 375 КБ, private 10–12 МБ (после `IDXGIDevice3::Trim` в свёрнутом состоянии; без него 15–17 МБ), CPU в покое 0. Цикл «раскрыть + свернуть» обычно 100–300 мс CPU, но иногда 0,8–1,7 с — WARP заново компилирует шейдеры. **После оптимизации** (слой плиток кэшируется в bitmap, анимации ~60 к/с на любом мониторе, пружины останавливаются на невидимых порогах): private ≈ 9 МБ; большинство анимаций 0–30 мс CPU, худший случай ~0,36 с (было до 1,7 с). Статистика кадров: `WIN_ISLAND_STATS=1` → `%TEMP%\win-island-stats.log`.
**Замер после этапа 3** (часы + погода): private ≈ 6 МБ в покое, 2 смены минуты за 70 с = 16 мс CPU. HTTP — встроенный WinHTTP (без TLS-крейтов). Погода: Open-Meteo, при недоступности `api.open-meteo.com` (в сети пользователя TLS-рукопожатие сбрасывается) — автоматический переход на wttr.in до конца сеанса. Город — `weather_city` в конфиге; пусто = погода выключена.
**Замер после этапа 4** (медиа): exe ≈ 530 КБ. Медиа-поток ждёт событий SMTC; Winamp/AIMP опрашиваются раз в 2 с только когда SMTC ничего не играет. Обложка декодируется один раз на трек (WIC, 160×160). Прогресс тикает раз в секунду только при раскрытом острове.
**Замер после этапа 5** (тексты + бит, музыка играет, остров свёрнут, 20 с): без `beat_edge` 16–31 мс CPU, ~16 МБ; с `beat_edge` 0,7–0,8 с CPU (~4 % одного ядра), ~18–20 МБ. Тексты — LRCLIB, кэш в `%APPDATA%\win-island\lyrics`, строка меняется по одноразовому таймеру. Бит — WASAPI loopback, двухполюсный ФНЧ 150 Гц, всплеск энергии > 1,6× среднего; захват идёт только во время воспроизведения; кадры «пляски» края ~30 к/с. `Trim()` рендера — через 10 с простоя (раньше после каждого кадра, что заставляло WARP перекомпилировать шейдеры).
**Замер после этапа 6** (буфер + док): в покое 15–21 МБ, 0 мс CPU. Иконки дока берутся `PrivateExtractIconsW` прямо из файла (ярлыки — через `IShellLinkW`): системный список иконок оболочки стоил ~12 МБ. WARP создаётся с `D3D11_CREATE_DEVICE_PREVENT_INTERNAL_THREADING_OPTIMIZATIONS`: меньше потоков (19 вместо ~30) и в ~2,5 раза меньше CPU при пульсации края. История буфера — `%APPDATA%\win-island\clipboard\history.json` + PNG; записи с пометками `ExcludeClipboardContentFromMonitorProcessing` / `CanIncludeInClipboardHistory=0` не сохраняются.
**Этап 9** (полноэкранный режим): события — `ABN_FULLSCREENAPP` (остров зарегистрирован как appbar без резерва места) и хук `EVENT_SYSTEM_FOREGROUND`; проверка — активное окно закрывает весь монитор острова (рабочий стол и панель задач не в счёт). Остров уезжает вверх и окно скрывается целиком. Пока спрятан — опрос курсора 10 раз/с только в этом состоянии (глобальный хук мыши не используется, чтобы не добавлять задержку ввода в играх); у верхнего края остров выезжает, без наведения прячется снова через 1,2 с. Уведомления в полноэкранном режиме не показываются. Настройка `hide_in_fullscreen`.
**Над развёрнутыми окнами** (`shrink_under_windows`): если активное окно доходит до верхнего края и перекрывает центр острова, свёрнутый остров становится полоской 100×6 DIP у самого края (акцентного цвета, пока играет музыка; без пульсации). Проверка — при смене активного окна и раз в 500 мс (одно `GetWindowRect`). В этом режиме остров раскрывается от самого края, без отступа. **Задержка наведения** `hover_delay_ms` = 300 мс везде; клик по свёрнутому острову раскрывает сразу.
**Решения (11.11.2026):** ИИ-чат — WebView2 по требованию (создаётся при открытии, уничтожается при закрытии); перевод — бесплатный сервис без ключа; персонажи (этап 13) — не делаем.
**Новое сверх плана (сделано):** активное окно (уведомление с иконкой и названием при переключении + плитка «Окно» с кнопками «поверх всех» / прозрачность 100→85→70 % / свернуть); громкость (колбэк `IAudioEndpointVolume`) и яркость (`GUID_VIDEO_CURRENT_MONITOR_BRIGHTNESS`) с полосой уровня; камера/микрофон (реестр `CapabilityAccessManager\ConsentStore` + `RegNotifyChangeKeyValue`, зелёная/оранжевая точка и уведомление); раскладка и Caps Lock (сырой ввод с клавиатуры: Caps — по нажатию, раскладка — проверка через 120 мс после отпускания Shift/Alt/Ctrl/Win/Пробела; `HSHELL_LANGUAGE` в этой системе не приходит). Настройки `show_active_app`, `osd`, `privacy_indicator`.
Рендер по умолчанию — программный WARP: аппаратный D3D-драйвер сам по себе добавлял ~50 МБ private. `gpu = true` в конфиге включает видеокарту.

Принципы:
- **Без WebView/Electron/Tauri/egui.** Чистый Win32 + Direct2D/DirectWrite/DirectComposition через крейт `windows`.
- **Только события, без поллинга**: SMTC-события, `AddClipboardFormatListener`, `SetWinEventHook`, WLAN-уведомления, `RegisterHotKey`.
- **Ленивая инициализация**: тяжёлые модули (запись экрана, OCR, AI-чат, FFT-анализ звука) создаются при первом использовании и выгружаются после.
- **Без tokio**: `std::thread` + каналы (`std::sync::mpsc`), результаты отправляются в UI через `PostMessageW(WM_APP+n)`.
- Модули — **cargo features**, чтобы можно было собрать минимальную версию.

## 2. Архитектура

```
island.exe (один процесс)
├── UI-поток: окно, цикл сообщений, рендер (D2D + DComp), анимации, hit-test
├── core: шина событий (enum Event) → state machine острова (Idle/Compact/Expanded/Activity)
├── services (по потоку на сервис, спят в ожидании событий):
│   ├── media      — SMTC (WinRT) + AIMP/Winamp IPC + громкость приложения
│   ├── lyrics     — LRCLIB (синхронизированные тексты), кэш на диске
│   ├── beat       — WASAPI loopback + FFT (только когда играет музыка и остров виден)
│   ├── weather    — Open-Meteo, раз в 30 мин
│   ├── clipboard  — история буфера
│   ├── system     — Wi-Fi (WlanAPI), Bluetooth, VPN (RAS), питание
│   ├── fullscreen — детект полноэкранных приложений
│   ├── capture    — скриншоты/запись экрана (ленивый)
│   ├── agents     — мост с Claude Code / opencode (named pipe)
│   └── launcher   — Alt+Space поиск
└── settings: отдельное окно, создаётся по требованию; конфиг в %APPDATA%\island\config.toml
```

### Окно
- `WS_POPUP` + `WS_EX_TOOLWINDOW | WS_EX_TOPMOST | WS_EX_NOACTIVATE | WS_EX_NOREDIRECTIONBITMAP` — нет в таскбаре, не крадёт фокус.
- Прозрачность и форма: DirectComposition visual с premultiplied alpha; клики вне формы острова пропускаются через `WM_NCHITTEST → HTTRANSPARENT` (или динамический `SetWindowRgn`).
- Per-Monitor DPI v2, привязка к выбранному монитору, переезд при смене конфигурации.
- Наведение: `TrackMouseEvent` (`WM_MOUSEHOVER`/`WM_MOUSELEAVE`) → раскрытие.

### Рендер и анимации
- Direct2D device context на swap chain DComp; DirectWrite для текста (Segoe UI Variable); WIC для обложек.
- Пружинная физика (spring: stiffness/damping) для размеров/радиусов/прозрачности.
- «Жидкий» край: контур острова — `ID2D1PathGeometry` с синусоидальными смещениями нижней кромки; амплитуда = уровень баса (beat) или «щетина» при таймере.
- Кадровый цикл включается только пока есть активная анимация (`DCompositionWaitForCompositorClock` / vsync), потом поток засыпает.
- Тёмная/светлая тема, акцентный цвет, прозрачность, размер — из конфига.

## 3. Функции (по видео) и как реализовать

| Функция | Реализация на Windows |
|---|---|
| Компактный вид: время, погода | DirectWrite; погода — Open-Meteo (без ключа), геолокация по IP или город в настройках |
| Раскрытие при наведении, «Главная» из плиток, перестройка под оставшиеся | Сеточный layout-движок (своя простая flex/grid-раскладка), плитки включаются/выключаются в настройках |
| Музыка: обложка, управление, прогресс | `GlobalSystemMediaTransportControlsSessionManager` (WinRT), подписка на события, обложка через `TryGetMediaPropertiesAsync().Thumbnail` |
| AIMP и Winamp | Winamp: `WM_USER`-IPC на окно `Winamp v1.x`; AIMP: Remote API (`AIMP2_RemoteInfo` shared memory + `WM_AIMP_COMMAND`). Активируется только если найдено окно плеера |
| Слова песни в такт | LRCLIB API (`/api/get` по артисту/треку/длительности), парсинг LRC, синхронизация по позиции SMTC |
| Край «танцует под бит» | WASAPI loopback, 1024-точечный FFT (`realfft`), энергия низких частот ~30 Гц; только при воспроизведении и видимом острове |
| Громкость плеера отдельно | `IAudioSessionManager2` → `ISimpleAudioVolume` сессии по PID процесса плеера |
| Погода «живыми плитками» (ветер, давление, влажность, восход/закат, УФ) | Тот же Open-Meteo, кастомная отрисовка компаса/дуг/шкал в D2D, анимация чисел при открытии вкладки |
| Скриншот области + рисование (стрелки, рамки, текст, размытие) → в буфер | Захват: `BitBlt`/DXGI Desktop Duplication; оверлей-редактор на D2D; копирование `CF_DIB` + PNG |
| Текст со скриншота, перевод | OCR: встроенный `Windows.Media.Ocr` (бесплатно, офлайн); перевод — внешний API (решить, какой) |
| QR-код, пипетка, «чистый текст», регистр/транслит/JSON/Base64 | `rqrr` для QR; `GetPixel` с лупой; текстовые преобразования — чистый Rust |
| Запись экрана со звуком (компьютер / +микрофон) | `Windows.Graphics.Capture` + Media Foundation `IMFSinkWriter` (аппаратный H.264, MP4); звук — WASAPI loopback + микрофон, микширование |
| Wi‑Fi: выбрал, ввёл пароль, подключился | WlanAPI: `WlanScan`, `WlanGetAvailableNetworkList`, `WlanSetProfile` (XML-профиль) + `WlanConnect` |
| Bluetooth-наушники | Список сопряжённых устройств (`Windows.Devices.Enumeration`), подключение аудио через `BluetoothSetServiceState` / `AudioPlaybackConnection` |
| VPN | Встроенные VPN-профили через RAS API (`RasEnumEntries`, `RasDial`, `RasHangUp`) |
| Блокировка/сон/перезагрузка/выключение | `LockWorkStation`, `SetSuspendState`, `InitiateShutdownW` |
| Скрытие в полноэкранном режиме, выход по курсору у верхнего края | `SetWinEventHook(EVENT_SYSTEM_FOREGROUND)` + `SHQueryUserNotificationState` + сравнение rect окна с монитором; когда скрыт — невидимая полоска 1–2 px вверху ловит наведение |
| Claude Code: разрешения и вопросы прямо на острове | Хуки Claude Code (`PermissionRequest`, `Notification`, `Stop`) вызывают `island-hook.exe` → named pipe → остров показывает вопрос → ответ возвращается в хук как JSON-решение |
| opencode | Плагин/подписка на события сервера opencode (SSE) → та же шина `agents` |
| История буфера | `AddClipboardFormatListener`; хранение в SQLite (`rusqlite`, bundled) или в простом бинарном журнале; картинки — миниатюры |
| Полка для файлов | OLE `IDropTarget` на окне острова, хранение ссылок/копий во временной папке |
| Alt+Space — поиск | `RegisterHotKey`; источники: ярлыки меню «Пуск», недавние файлы, Everything SDK (если установлен); действия «спросить ИИ», «искать в браузере» |
| Заметки, таймер, напоминания | Свой модуль; таймер — `CreateWaitableTimer` (без поллинга), уведомление — активность на острове |
| Уведомление «Скопировано» и т.п. | Внутренние Activity с приоритетами и очередью |
| Персонажи («Глазок» и др.): следят за курсором, «думают», пугаются таймера | Векторные персонажи в D2D, состояния idle/thinking/alarm; курсор — `GetCursorPos` 20 Гц **только** пока персонаж виден и курсор двигается |
| Перекраска, светлая/тёмная тема по клавише, превью настройки на острове при наведении | Окно настроек (D2D, тот же UI-тулкит); hover по строке → событие → остров показывает превью |
| AI-чат (Gemini, DeepSeek) во вкладке и отдельном окне | **Требует решения** (см. ниже) |
| Автозапуск, трей | `HKCU\...\Run`, `Shell_NotifyIconW` |

## 4. Этапы

1. **Каркас** — окно, DComp + D2D, пилюля-остров, 0 % CPU в покое, трей, конфиг, автозапуск. *Замер ресурсов.*
2. **UI-движок** — пружинные анимации, раскрытие по наведению, жидкий край, layout плиток, тема/цвета.
3. **Компактный вид** — время + погода.
4. **Медиа** — SMTC, обложка, управление, громкость приложения; AIMP/Winamp.
5. **Лирика и бит** — LRCLIB + WASAPI/FFT.
6. **Главная** — настраиваемые плитки, док приложений, история буфера.
7. **Инструменты экрана** — скриншот + редактор, OCR, QR, пипетка, текстовые преобразования.
8. **Центр управления** — Wi‑Fi, Bluetooth, VPN, питание.
9. **Полноэкранный режим** — скрытие и выход по верхнему краю.
10. **Мост с агентами** — Claude Code hooks + opencode.
    *Сделано:* именованный канал `win-island-agent-<user>` (доступ только владельцу), `island-hook.exe` для хуков PermissionRequest / AskUserQuestion / Notification / Stop, плагин opencode (`integrations/opencode`). Карточка с кнопками «Терминал / Нет / ✓»; без ответа за 50 с или если хук закрыли — вопрос остаётся в терминале. Хелпер 230 КБ; остров +1 поток в покое.
11. **Alt+Space, заметки, таймер, напоминания, полка файлов.**
12. **Запись экрана** со звуком.
13. **Персонажи.**
14. **Окно настроек** с живым превью.
15. **AI-чат** (по выбранному варианту).

После каждого этапа — замер RAM/CPU (Process Explorer / `GetProcessMemoryInfo`) против бюджета.

## 5. Стек

- `windows` (Win32 + WinRT: D2D, DWrite, DComp, WIC, Media.Control, Media.Ocr, Graphics.Capture, WLAN, RAS, Core Audio, MF)
- `serde` + `toml` — конфиг; `serde_json` — API и хуки
- `ureq` (блокирующий HTTP, rustls) — погода/лирика
- `realfft` — бит; `rqrr` — QR
- `rusqlite` (bundled) — опционально для буфера/заметок
- Сборка: `cargo build --release`, MSVC toolchain, `windows_subsystem = "windows"`, манифест с DPI-awareness и Common Controls v6

## 6. Вопросы для согласования

1. **Объём MVP**: какие этапы делаем первыми? Предлагаю 1–6 + 9 как первую версию.
2. **AI-чат «без ключей, просто войди в аккаунт»** — это возможно только через встроенный браузер (WebView2), а он съедает 80–150 МБ. Варианты: (а) API-ключи и нативный UI — дёшево; (б) WebView2, создаётся только при открытии чата и уничтожается при закрытии; (в) не делать.
3. **Перевод текста**: какой сервис (DeepL / Google / LLM)?
4. **Поддержка Windows 10** нужна или только 11 (на 11 проще со скруглениями и Mica)?
5. **Персонажи**: сколько на старте (1–3 вместо 25)? Свой стиль рисуем вместе.
6. **Хранение истории буфера**: SQLite (+~1 МБ к бинарнику) или простой файл?
7. **Название** проекта и нужен ли инсталлятор (MSI/winget) или portable .exe.
