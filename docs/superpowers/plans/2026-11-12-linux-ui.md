# Linux GTK application implementation plan

> **For agentic workers:** Use subagent-driven-development or executing-plans to implement this milestone task by task.

**Goal:** Build and exercise a native Rust GTK application as the first Linux UI milestone toward the complete Ubuntu port.

**Architecture:** A standalone `apps/linux` package consumes the shared core and the owner-pinned MPRIS adapter. GTK owns the main loop and widgets; blocking media and network operations run on workers. The GNOME extension handles compositor-only operations through the versioned Shell1 contract.

**Tech Stack:** Rust 2021, gtk4-rs 0.9.7 with GTK 4.14 APIs, libadwaita 0.7.2 with 1.5 APIs, zbus 5.

**Spec:** [Ubuntu architecture](../../ubuntu/architecture.md).

## Global constraints

- Ubuntu 24.04 LTS amd64 is the build baseline; Ubuntu 26.04 LTS is a compatibility target.
- Main application and rendering remain Rust, using native GTK widgets.
- Existing Windows behavior and legacy data paths must remain intact.
- Shared models have a single source in `crates/tidemark-core`.
- A missing backend is reported as unsupported; it must never produce a fabricated success.
- The Ubuntu release remains gated on the full feature matrix and desktop acceptance tests.

## Review focus

- Startup with no GNOME adapter must remain usable, and existing instances must retain their state during any explicit handover.
- Songs and the globally current player may change while a music sleep timer targets its captured session.
- Compact/expanded allocations and input regions must match the visible island, including transparent margins.
- File/image clipboard entries and artwork must retain bounds and privacy markers when backends are integrated.
- GTK callbacks must stay on the main context, with no blocking media/network calls or overlapping mutable borrows.

## Tasks

1. **Shared UI model** — `apps/linux/src/model.rs`, `Cargo.toml`, `Cargo.lock`.
   - [x] Consume config, history, notes, timers and text tools from the core.
   - [x] Check URI handling, model formatting and config mappings with portable model tests.
2. **Native construction** — `apps/linux/src/app.rs`, `src/ui/*.rs`.
   - [x] Create the island, tab views and native settings with explicit unavailable states.
   - [ ] Compile the actual GTK code on Ubuntu; Windows model tests cannot validate GTK APIs.
   - [ ] Exercise all initial views and settings through the deterministic smoke entrypoint.
   - [ ] Verify compact/expanded geometry and click-through input regions after a real frame.
3. **Media worker** — `apps/linux/src/services/music.rs`.
   - [x] Keep D-Bus operations off the GTK main loop and use captured MPRIS owners.
   - [x] Report sleep success only after the paused state is confirmed.
   - [ ] Integrate the bounded artwork crate and the shared late-art retry schedule.
   - [ ] Verify normal playback and volume behavior with real Linux players.
4. **GNOME client** — `apps/linux/src/services/shell.rs` and UI adapters.
   - [x] Add preflight/Hello protocol entry points matching the extension's actual bus and role identifiers.
   - [ ] Retain the authenticated bus connection and consume unicast signals.
   - [ ] Wire window actions, background clipboard capture, shortcuts and state updates.
   - [ ] Exercise the consented handover path without losing notes, clipboard or active timers.
5. **Native checks and package** — `.github/workflows/ubuntu.yml`, `scripts/package-linux.sh`, `installer/linux/*`.
   - [x] Prepare native compile, package install/remove and isolated GTK smoke jobs.
   - [ ] Run them on Ubuntu 24.04 and inspect rendered artifacts.
   - [ ] Verify the baseline-built package on Ubuntu 26.04.
6. **Full parity** — follow the existing architecture matrix, including real Yandex likes, capture/editor/OCR/QR/recording, shelf/dock, search, lyrics/weather and system controls. These remain separate acceptance requirements; this milestone does not declare them complete.
