# Tidemark connection to bb

Approved direction: a separately installable bb plugin and a native Tidemark connection. The user requested immediate implementation, builds, and GitHub publication.

The plugin exposes token-authenticated state, answer, and message routes using the current bb SDK. Tidemark stores the server address and token locally, polls for pending interactions on a background thread, and surfaces new questions on the island. Opening the bb panel shows full questions, choices, and a free text response; selecting a thread permits sending additional instructions. Existing Claude Code and opencode integrations remain compatible.

Approaches: provider-specific hooks would miss other bb providers; a standalone notification bridge would not support writing messages. A plugin API plus native client supports both and works with remote HTTPS servers.

Constraints: Windows native UI; no embedded browser; no user-specific paths or credentials in published artifacts; explicit user actions for every answer or message; stale interactions must be rejected by bb. No automatic approvals. HTTP is accepted only for loopback; remote connections require HTTPS. The token grants access to threads through this plugin and must be stored separately from general settings.

Deliverables: Tidemark binaries and portable/installer packages, independent bb plugin repository with installation instructions, source and release publication on GitHub. Verification includes API validation and stale-answer tests, Rust tests and release build, plugin typecheck/build, and a local live connection check.
